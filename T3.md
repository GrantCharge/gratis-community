# T3 environments

Use Tasks to connect one or more existing T3 MCP environments by address — for example a laptop on your tailnet and a VPS. This edition deliberately does not replace a system-wide T3 service. Follow [the T3 Agents headless setup](https://github.com/GrantCharge/t3code/blob/main/docs/operations/headless-linux.md) to run an environment you control, then add it under **T3 environments** and authorize the connection in your browser.

Each environment keeps its own address, OAuth tokens and encrypted connection file, so adding a second one never signs you out of the first. Remote addresses must use HTTPS (Tailscale Serve works); loopback addresses may use HTTP. You can rename, reconnect or remove an environment. Removal is refused while that environment still has unfinished tasks, and it clears the bot settings that pointed at it.

Each bot chooses one environment, then a project, model and either a new or existing thread. Project and thread IDs belong to the host that created them, so changing a bot's environment clears its project choice. Every task remembers its environment: follow-ups, refreshes and stop requests go back to the same host, and one host being offline never blocks tasks on another. Task cards and result messages name the environment.

Submit a self-contained task with clear acceptance criteria. T3 work belongs to its host and continues independently of the Gratis window, but that host must stay awake and reachable. Results return when Gratis reconnects.

Upgrading from a single connection keeps it as the first environment with its tokens and bot settings intact.

T3 permissions, filesystem access, provider authentication and runtime approvals are configured in T3. Gratis does not silently forward its Composio credentials. Deleting a local conversation does not cancel independent T3 work; stop it first through Tasks or T3.
